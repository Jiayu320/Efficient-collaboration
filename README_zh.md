# 高效的 LLM 协同推理框架

高效 LLM 协同推理框架 (Efficient LLM Collaboration Inference) 是一个先进的系统，旨在优化多个大型语言模型 (LLM) 的协同推理过程。通过利用自动任务分解、动态模型分配和并行处理，该系统能够高效地解决单个模型难以应对的复杂问题。

-----

## 核心特性

  - **自动任务分解**: 利用一个成熟的“规划器”(Planner)模型将复杂问题分解为由一系列更小、可管理的子任务组成的有向无环图 (DAG)。
  - **动态模型分配**: 根据每个子任务的预估难度，智能地为其分配最合适的模型（例如，更小、更快的模型或更大、更强大的模型）。
  - **并行任务执行**: 采用多线程调度器并行执行独立的子任务，显著减少了总处理时间。
  - **全面的性能监控**: 跟踪并报告详细的性能指标，包括执行时间、首个令牌生成时间 (TTFT)、令牌使用量和预估成本，为系统效率提供深入的洞察。
  - **批量处理与评估**: 支持对数据集进行批量处理和系统评估，从而实现稳健的模型和系统性能分析。

## 工作原理

该系统通过一个结构化的多阶段流程进行运作：

1.  **规划 (任务分解)**: 用户的查询首先被发送到一个 **规划器模型** (Planner Model)。该模型分析问题并生成一个详细的 XML 格式的执行计划。该计划概述了一系列步骤，每个步骤都包含具体的任务、预估的难度、令牌预算及其对其他步骤的依赖关系。
2.  **调度 (任务分派)**: 系统解析 XML 计划以构建任务依赖图 (DAG)。然后，调度器识别出所有依赖项已满足的任务，并将它们分派以供执行。
3.  **执行 (解决子任务)**: 每个被分派的任务都被发送到一个 **执行器模型** (Executor Model)。系统会根据计划中的 `Difficulty` (难度) 属性，为较简单的任务动态选择一个小型高效的模型（例如，`qwen2.5-3b-instruct`），或为较复杂的任务选择一个大型强大的模型（例如，`gpt-4o`）。
4.  **并行处理**: 调度器使用线程池并发执行多个独立的任务。当任务完成时，调度器会检查是否有新的任务因依赖满足而解锁，并将其添加到执行队列中。
5.  **聚合 (生成最终答案)**: 一旦计划中的所有任务都完成，系统会收集每个步骤的结果，并进行最终的聚合，以生成对原始查询的最终答案。
6.  **报告**: 流程结束后，系统会生成一份详细的报告，包括性能指标、成本分析、任务依赖图和量化的评估分数。

### 与其他方法的比较

与直接使用单一模型的方法相比，我们的协同推理方法在效率和解决方案质量上都表现出显著的改进。

## 安装与设置

1.  **克隆仓库**

    ```bash
    git clone https://github.com/Jiayu320/Efficient-collaboration.git
    cd Efficient-collaboration
    ```

2.  **安装依赖**

    建议首先创建一个虚拟环境。

    ```bash
    python -m venv venv
    source venv/bin/activate  # 在 Windows 上，使用 `venv\Scripts\activate`
    ```

    从 `requirements.txt` 文件中安装所需的包：

    ```bash
    pip install -r requirements.txt
    ```

    *(注意: 如果未提供 `requirements.txt` 文件，您可以根据 Python 文件中的导入语句推断依赖项，例如 `openai`, `pyyaml`, `tqdm`, 和 `transformers`。)*

3.  **配置 API 密钥和模型**

      - 复制配置文件示例：
        ```bash
        cp config.example.yaml config.yaml
        ```
      - 编辑 `config.yaml` 文件，设置您的模型和 API 凭证。
      - 将您的 API 密钥放置在 `*_key_path` 变量指定的文件中（例如，在一个名为 `usage/` 的文件夹中）。
        ```yaml
        models:
          small_model: qwen2.5-3b-instruct
          large_model: gpt-4o
          router_model: gemini-2.5-pro # 规划器模型
          threshold: 4 # 难度低于 4 的任务使用小模型

        api:
          small_key_path: usage/qwen_key
          large_key_path: usage/openai_key
          router_key_path: usage/google_key
          small_api_base_url: https://dashscope.aliyuncs.com/compatible-mode/v1
          large_api_base_url: https://api.openai.com/v1
          router_api_base_url: https://api.generativeai.google.com/v1
        ```

## 使用方法

该系统可以以两种模式运行：单一查询处理或批量数据集评估。

### 单一查询模式

要解决单个问题，请在 `config.yaml` 中定义 `query`，然后运行主脚本。

```bash
python main.py --config config.yaml
```

详细结果，包括性能报告和日志，将保存在 `data_reports/single/` 目录中，并按模型配置和时间戳进行组织。

### 数据集评估模式

要在数据集上评估系统性能，请在 `config.yaml` 中启用 `dataset` 部分，指定文件路径，然后运行脚本。

```yaml
# 在 config.yaml 中
dataset:
  enabled: true
  path: dataset/TestData/s1k_testPerformance.json
  limit: 30 # 可选：限制处理的问题数量
```

然后，执行主脚本：

```bash
python main.py
```

数据集报告将保存在 `data_reports/dataset/` 目录中。

## 评估框架

为确保我们系统的质量和可靠性，我们采用了一个严格的、分为两部分的评估框架，该框架使用一个强大的 LLM 作为裁判，对 **规划器** (Planner) 和 **执行器** (Executor) 模型进行评估。

### 规划器评估

规划器根据其生成高质量、机器可执行计划的能力进行评估。评估主要关注五个关键维度：

| 维度 | 描述 |
| --- | --- |
| **计划合理性与分解质量** | 评估计划是否正确且逻辑清晰地分解了问题。一个有缺陷的分解会使整个解决方案策略失效。 |
| **依赖结构与流程** | 评估任务依赖图（`Rely` 属性）的正确性，这对于最大化并行处理和确保上下文正确至关重要。 |
| **任务清晰度与可执行性** | 衡量每个任务是否是一个清晰、明确、可操作的指令，适合 AI 执行器执行。模糊的任务会导致执行效果不佳。 |
| **属性准确性** | 判断规划器对 `Difficulty` 和 `Token` 属性的估计是否准确，这对于高效的动态模型分配至关重要。 |
| **计划相关性与效率** | 检查是否存在冗余或无关的步骤。一个好的计划应该是精炼、有目的性且没有计算资源浪费的。 |

### 执行器评估

执行器模型根据其准确高效地执行由规划器分配的各个子任务的能力进行评估。

| 维度 | 描述 |
| --- | --- |
| **指令遵循与遵守度** | 评估模型在多大程度上遵守了所分配任务的具体约束和指令。 |
| **上下文有效利用** | 评估模型是否正确利用了先前步骤提供的结果来指导其自身的执行。 |
| **正确性与事实准确性** | 衡量模型响应在事实上和逻辑上的准确性。这是衡量任务成功与否的主要标准。 |
| **清晰度与机器可用性** | 判断输出是否清晰、结构良好，并且易于后续步骤解析。 |
| **相关性与简洁性** | 评估模型的响应是否简洁且严格与任务相关，避免了对话式的填充内容或无关信息。 |

## 模型训练

规划器模型可以是一个通用的顶尖模型，也可以是一个经过微调的较小模型。在我们的实验中，我们对一个 `Qwen3-1.7B-Instruct` 模型进行了微调，使其成为一个高效的规划器。微调是使用 **LLaMA-Factory** 框架，在一个包含高质量“问题-计划”配对的特制数据集上进行的。

## 代码库结构

本仓库中关键文件的简要概述：

| 文件 | 描述 |
| --- | --- |
| `main.py` | 应用程序的主入口点。处理参数解析并协调整个工作流程。 |
| `config.yaml` | 用于模型、API 密钥、系统设置和数据集路径的中央配置文件。 |
| `execution.py` | 包含并行任务执行、API 调用和规划器流式响应处理的核心逻辑。 |
| `dataset_runner.py` | 管理数据集的批量处理、生成结果并保存综合报告。 |
| `evaluation.py` | 实现用于评估规划器和执行器性能的评估框架。 |
| `performance.py` | `PerformanceTracker` 类，用于监控令牌使用、成本和执行时间等指标。 |
| `output_performance.py` | 根据模型特定的延迟和吞吐量数据计算理论性能基准。 |
| `config.py` | 定义 `ModelConfig` 类，用于管理模型配置和 API 客户端。 |
| `api_pricing.py` | 一个实用工具模块，提供各种 LLM API 的最新定价信息。 |
| `analyze_model_tasks.py`| 一个用于分析和报告小模型与大模型之间任务分配情况的脚本。 |
